Resumen Ejecutivo

Se entrega en pleno funcionamiento el Sistema de Gestión Central del FAB LAB INACAP Sede San Pedro de la Paz, una plataforma web accesible desde cualquier dispositivo y sin necesidad de instalación. El sistema centraliza el registro de visitas, la gestión de inventario con tecnología NFC, el control de ocupación del laboratorio, la administración de secciones de alumnos y la gestión de ayudantes con sus horarios semanales.

Todos los módulos acordados han sido implementados, probados y desplegados en producción. El sistema opera de forma gratuita sobre infraestructura en la nube y está disponible en línea de manera permanente.

Arquitectura Técnica

Frontend HTML5, CSS3 y JavaScript vanilla — sin frameworks ni build step. Desplegado en GitHub Pages (gratuito, permanente).
Visitas y Ocupación Google Apps Script como API serverless. Los datos se almacenan en Google Sheets con acceso mediante token de administración.
Inventario Supabase (PostgreSQL en la nube). Tablas: activos, préstamos, ayudantes. Plan gratuito con 500 MB de almacenamiento.
NFC Web NFC API con AbortController para lectura y escritura de tags NFC directamente desde el navegador (Chrome Android) o la app.
App Android Capacitor.js empaqueta la web como APK nativo. El CI/CD en GitHub Actions genera el APK automáticamente en cada actualización.
Infraestructura 100% en la nube. Sin servidor propio, sin costo de hosting. GitHub Pages + Supabase Free + Google Workspace INACAP.

Recomendaciones de Uso

NFC Usar Google Chrome en Android para la lectura y escritura de tags NFC. Safari y Firefox no son compatibles con la Web NFC API.
Exportación Las exportaciones a Excel y PDF funcionan directamente desde el navegador. No requieren software adicional.
Respaldo Los datos de visitas están en Google Sheets y son exportables en cualquier momento. Los datos de inventario están en Supabase con respaldo automático.
Actualizaciones Cualquier mejora al sistema se despliega automáticamente al repositorio GitHub. No hay acciones manuales requeridas por parte del cliente.
APK Android Descargar el archivo app-debug.apk desde la sección Actions del repositorio GitHub e instalar en el dispositivo Android del laboratorio.

Consideraciones de Seguridad

El sistema fue diseñado como prototipo funcional de gestión interna. A continuación se detallan los riesgos identificados, su nivel de impacto y las mitigaciones aplicadas o planificadas antes de un eventual paso a producción crítica.

Riesgo · Medio-Alto RLS de Supabase abierto

Las tablas assets, loans y ayudantes no tienen políticas RLS activas. La anon key es pública por diseño de Supabase, por lo que cualquier persona que la identifique en el código fuente puede consultar o modificar datos directamente a través de la API REST.

Mitigación planificada: el archivo supabase-rls.sql incluido en el repositorio contiene las políticas necesarias. Al ejecutarlo, las lecturas permanecen abiertas y las escrituras quedan restringidas a usuarios autenticados. El dashboard ya incluye la llamada signInWithPassword para activar la sesión autenticada automáticamente.

Resuelto Token de administración en código fuente

El token de autenticación al Google Apps Script fue eliminado del código fuente del dashboard y del formulario público. El Apps Script ya no requiere token para operar; el acceso al panel está protegido por login de Supabase.

Riesgo · Bajo (contexto actual) Autorización por roles solo en cliente

La lógica de control de acceso (qué puede hacer un usuario administrador vs. uno de solo lectura) se aplica únicamente en el frontend. No existe validación equivalente en el servidor. Un usuario con conocimiento técnico puede bypassear las restricciones de interfaz realizando llamadas directas a la API.

Mitigación a futuro: implementar validación server-side mediante Supabase Edge Functions o un backend dedicado que centralice la lógica de permisos. Clasificado como prioridad de trabajo futuro de alta relevancia para producción.

Para el contexto actual de uso interno en el FAB LAB INACAP, el nivel de riesgo es aceptable. Los datos gestionados (visitas, inventario, horarios) no son sensibles en términos de privacidad crítica. Se recomienda aplicar las mitigaciones indicadas antes de ampliar el acceso del sistema a usuarios externos o integrar datos personales adicionales.
